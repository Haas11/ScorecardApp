# KNBSB Scorecard Pipeline

Digitizes Dutch KNBSB baseball scorecards into structured JSON, a SQLite database, an Excel workbook, and a color-coded HTML widget — using Gemini 2.5 Flash as the VLM backbone.

For pipeline architecture and internals, see [CLAUDE.md](CLAUDE.md).

## Setup

```powershell
cd scorecard
uv sync
```

Create `scorecard/.env` with your Gemini API key (gitignored — never commit it):

```
GOOGLE_API_KEY=AIza...
EXTRACTION_MODEL=gemini-2.5-flash
```

```

      2026-04-12 - Thamen (Home)_grid_debug.png
      2026-04-12 - Thamen (Home).html         ← color-coded visual widget
      ground_truth_totals.txt   ← optional; per-inning R/H/E/LOB

  scans/                        ← drop scan images here
  players.txt                   ← team roster (name, jersey per line)
  season.db                     ← SQLite database (gitignored)
  Quick 2026 stats.xlsx         ← generated by export_season.py (gitignored)

scorecard/
  extract_cells.py    ← main pipeline
  probe_grid.py        ← OpenCV grid (row/column) detection
  reimport.py          ← reimport _cells.json → DB + regenerate HTML; --sync-cells to reverse-write cell cache
  crawl.py              ← re-run --reuse-cache across all/some game folders (e.g. after adding a new field)
  export_season.py     ← Excel export

  mark_reviewed.py     ← bulk-mark PAs as reviewed
  manage_players.py    ← player alias management
  render_widget.py     ← standalone HTML widget renderer
  stats.py              ← derived stat calculations (AVG, OBP, SLG, wOBA, OPS+, …)
  db.py, models.py, config.yml
```

## Image naming

Name scan files as `YYYY-MM-DD - <Opponent> (Home|Away).jpg` and place them in `Quick 2026/scans/`. Date, opponent, and home/away are parsed from the filename. Outputs land under `Quick 2026/games/{stem}/`.

## Processing a game

All commands run from the `scorecard/` directory.

### 1 — Run the extraction

```powershell
uv run python extract_cells.py "../Quick 2026/scans/2026-06-07 - Almere (Away).jpg"
```

The pipeline detects the grid, reads player names/subs, classifies every PA cell via the VLM, enforces logical/structural rules, cross-checks against ground truth, then writes `_cells.json` / `_grid_debug.png` / `.html` and imports into `season.db`.

### 2 — Check the output

Open the generated `.html` widget. Color coding: **green** = hit, **blue** = reached base without a hit (BB/HBP), **yellow** = error/FC/K-PB, **red** = out. Also check the terminal for `MISMATCH` lines.

### 3 — (Optional) supply ground truth

**`ground_truth_totals.txt`** — per-inning team totals:
```
# inning  runs  hits  errors  lob
1  3  1  2  0
```

**`ground_truth_stats.txt`** — per-player H and AB (repeat a slot for a sub):
```
# slot  H  AB
1  3  4
5  1  4
5  1  1
```

### 4 — Re-run with cache

```powershell
uv run python extract_cells.py "../Quick 2026/scans/2026-06-07 - Almere (Away).jpg" --reuse-cache
```

`--reuse-cache` skips API calls for cells already classified; structural rules always re-run. Repeat 2–4 until checks pass.

### Grid detection overrides (low-res / landscape / skewed scans)

If grid auto-detection produces a wrong column/row count or spacing, check the debug image (`*_grid_debug.png`) and override manually:

| Flag | Use for |
|---|---|
| `--left-skip 0.35` | Wide player-info area throwing off V-line detection (increase from default 0.05) |
| `--grid-start 455 --grid-width 75` | Bypass V-line detection entirely; force a uniform column grid |
| `--cell-height 74` | Bimodal H-line detection picks the wrong row height (e.g. sub-row divider height instead of full row) |
| `--reset-names` | Delete the cached player names and re-detect from scratch (use with `--reuse-cache` to keep cell reads) |

## Correcting a PA after extraction

**Interactive reviewer** (recommended for low-confidence flags):
```powershell
uv run python review.py --game 2026-06-07          # only low-confidence flags
uv run python review.py --game 2026-06-07 --all    # every PA in the game
```

**Manual edit:** edit `Quick 2026/games/{stem}/{stem}_cells.json` directly, then:
```powershell
uv run python reimport.py "../Quick 2026/games/2026-04-12 - Thamen (Home)/2026-04-12 - Thamen (Home)_cells.json"
```

If you hand-edit `_cells.json`, the per-cell cache (`cells/r##_c##.json`) still holds the old values and will overwrite your edit on a future `--reuse-cache` run. Sync it back first:
```powershell
uv run python reimport.py --sync-cells "../Quick 2026/games/{stem}/{stem}_cells.json"
```

## Bulk operations

Reimport every game (after a DB/stat logic change):
```powershell
uv run python reimport.py --all "../Quick 2026/games"
```

Backfill a new per-cell field (e.g. stolen bases) across already-analyzed games without re-doing VLM classification:
```powershell
uv run python crawl.py "../Quick 2026/games"
uv run python crawl.py "../Quick 2026/games" --game "2026-04-12"   # single game by date fragment
```

## Export to Excel

```powershell
uv run python export_season.py
```

Output: `Quick 2026/Quick 2026 stats.xlsx`

| Sheet | Contents |
|---|---|
| Season Stats | Cumulative stats for all players, sorted by OPS |
| Game Log | Per-player per-game line |
| {Date} {Opponent} | Box score for each game |
| Low Confidence | PAs flagged for review |

Stats: PA, AB, H, 2B, 3B, HR, BB, K, R, RBI, SB, AVG, OBP, SLG, OPS, BABIP, ISO, BB%, K%, wOBA, RC, OPS+, AB/HR, BB/K. BB, HBP, SAC, and SF do not count as an AB.

## Publish outputs

Copy all HTML widgets and the stats xlsx to a shared folder (e.g. Google Drive):
```powershell
uv run python publish.py "../Quick 2026" "G:\My Drive\Quick 2026"
```

## Roster

Player names are detected from the scorecard automatically and fuzzy-matched against `Quick 2026/players.txt`. Substitutions share the same batting slot and are detected from the info strip.

```powershell
uv run python manage_players.py list
uv run python manage_players.py aliases    # audit recent fuzzy matches
```

## Notes

- **API key safety**: `.env` is gitignored. Never commit API keys. (Org policy: CMMC, CRA, PCI, TISAX, EU AI regulations apply.)
