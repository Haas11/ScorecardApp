# KNBSB Scorecard Pipeline

Digitizes Dutch KNBSB baseball scorecards into structured JSON, a SQLite database, and an Excel workbook.

## Setup

```powershell
cd scorecard
uv sync
```

Create `scorecard/.env` with your Gemini API key:

```
GOOGLE_API_KEY=AIza...
EXTRACTION_MODEL=gemini-2.5-flash
```

```
  games/

      ground_truth_totals.txt   ← optional; hand-correct to guide extraction

  reimport.py         ← reimport an edited _cells.json into the DB + regenerate HTML
  export_season.py    ← Excel export

  manage_players.py   ← player alias management
  render_widget.py    ← standalone HTML widget renderer

```

## Image naming

Name scan files as `YYYY-MM-DD - <Opponent> (Home|Away).jpg` and place them in `Quick 2026 data/scans/`:

```
Quick 2026 data/scans/
  2026-06-07 - Almere (Away).jpg
  2026-04-12 - Thamen (Home).jpg
```

Date, opponent, and home/away are parsed from the filename. All outputs (cells.json, HTML, grid debug image) are placed under `Quick 2026 data/games/{stem}/`.

## Processing a game — step by step

All commands run from the `scorecard/` directory.

### Step 1 — Run the extraction

```powershell
uv run python extract_cells.py "../Quick 2026 data/scans/2026-06-07 - Almere (Away).jpg"
```

The pipeline:
1. Auto-detects the grid (row/column boundaries) — no parameters needed
2. Classifies each PA cell via Gemini 2.5 Flash (cached per cell)
3. Applies structural rules (isolation, 3-out, K-PB)
4. Cross-checks against ground-truth totals if present
5. Writes `_cells.json`, `_grid_debug.png`, and `.html` widget under `games/{stem}/`
6. Imports into `season.db`

### Step 2 — Check the output

Open the generated `.html` widget to visually review the scorecard.

Also read the terminal output for:
- `MISMATCH` lines in per-player or per-inning checks
- `[isolated]` or `[3-outs]` removals
- `Outs:WARNING` is **expected** (runner outs from FC/SB don't appear in PA results)

### Step 3 — Edit ground-truth files if needed

Two optional ground-truth files live in `Quick 2026 data/games/{stem}/`:

**`ground_truth_totals.txt`** — per-inning team totals from the card's bottom strip:
```
# inning  runs  hits  errors  lob
1  3  1  2  0
2  0  2  0  2
```

**`ground_truth_stats.txt`** — per-player H and AB from the stats column:
```
# slot  H  AB
1  3  4
5  1  4
5  1  1     ← second row for same slot = substitution
```

### Step 4 — Re-run with cache

```powershell
uv run python extract_cells.py "../Quick 2026 data/scans/2026-06-07 - Almere (Away).jpg" --reuse-cache
```

`--reuse-cache` skips API calls for cells already classified. Structural rules always re-run from scratch. Repeat steps 2–4 until all checks show OK.

## Correcting a PA after extraction

1. Open `Quick 2026 data/games/{stem}/{stem}_cells.json` in any text editor
2. Find the PA under `lineup[].players[].plate_appearances[]` and fix `result` / `run_scored`
3. Reimport (updates DB + regenerates HTML):

```powershell
uv run python reimport.py "../Quick 2026 data/games/2026-04-12 - Thamen (Home)/2026-04-12 - Thamen (Home)_cells.json"
```

4. Refresh the season Excel (optional):

```powershell
uv run python export_season.py
```

Alternatively, use the interactive reviewer for low-confidence flags:

```powershell
uv run python review.py --game 2026-06-07          # only low-confidence flags
uv run python review.py --game 2026-06-07 --all    # every PA in the game
```

## Export to Excel

```powershell
uv run python export_season.py
```

Output: `Quick 2026 data/season_stats.xlsx`

| Sheet | Contents |
|---|---|
| Season Stats | Cumulative stats for all players, sorted by OPS |
| Game Log | Per-player per-game line |
| {Date} {Opponent} | Box score for each game |
| Low Confidence | PAs flagged for review |

## Roster file

`Quick 2026 data/players.txt` lists one player per batting slot (name, jersey number):

```
Max. Gelaudi, 98
Joey Bradwell, 71
Victor van Spaandonk, 24
```

Substitutions are detected automatically from the scorecard and share the same batting slot.

---

## Players and aliases

Fuzzy name matching runs automatically during import. Names scoring ≥ 70 similarity are matched without manual confirmation; names scoring < 50 create a new DB entry.

```powershell
uv run python manage_players.py list
uv run python manage_players.py aliases    # audit recent fuzzy matches
```

---

## Notes

- **API key safety**: `.env` is gitignored. Never commit API keys.
- **Re-running a game**: run the same extract command again — the pipeline replaces any existing DB entry automatically.
- **DB path**: driven by `paths.data_root` in `scorecard/config.yml`; currently `../Quick 2026 data`.
