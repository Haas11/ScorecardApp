# KNBSB Scorecard Pipeline

Digitizes Dutch KNBSB baseball scorecards into structured JSON, a SQLite database, an Excel workbook, and a color-coded HTML widget — using Gemini 2.5 Flash as the VLM backbone.

## Setup

```powershell
cd scorecard
uv sync
```

Create `scorecard/.env` with your Gemini API key:

```
GOOGLE_API_KEY=AIza...
EXTRACTION_MODEL=gemini-2.5-flash
```

## Directory layout

```
Quick 2026/
  games/
    2026-04-12 - Thamen (Home)/
      cells/                    ← per-cell VLM cache (gitignored)
      2026-04-12 - Thamen (Home)_cells.json   ← main output; edit to fix errors
      2026-04-12 - Thamen (Home)_grid_debug.png
      2026-04-12 - Thamen (Home).html         ← color-coded visual widget
      ground_truth_totals.txt   ← optional; per-inning R/H/E/LOB
      ground_truth_stats.txt    ← optional; per-player H/AB
  scans/                        ← drop scan images here
  season.db                     ← SQLite database (gitignored)
  Quick 2026 stats.xlsx         ← generated by export_season.py (gitignored)

scorecard/
  extract_cells.py    ← main pipeline
  reimport.py         ← reimport one or all _cells.json files into DB + regenerate HTML
  export_season.py    ← Excel export
  review.py           ← interactive low-confidence PA review
  publish.py          ← copy HTML widgets + xlsx to a destination folder
  mark_reviewed.py    ← bulk-mark PAs as reviewed
  manage_players.py   ← player alias management
  render_widget.py    ← standalone HTML widget renderer
  stats.py            ← derived stat calculations (AVG, OBP, SLG, wOBA, OPS+, RC, …)
  db.py, models.py, probe_grid.py, config.yml
```

## Image naming

Name scan files as `YYYY-MM-DD - <Opponent> (Home|Away).jpg` and place them in `Quick 2026/scans/`:

```
Quick 2026/scans/
  2026-06-07 - Almere (Away).jpg
  2026-04-12 - Thamen (Home).jpg
```

Date, opponent, and home/away are parsed from the filename. All outputs are placed under `Quick 2026/games/{stem}/`.

## Processing a game — step by step

All commands run from the `scorecard/` directory.

### Step 1 — Run the extraction

```powershell
uv run python extract_cells.py "../Quick 2026/scans/2026-06-07 - Almere (Away).jpg"
```

The pipeline:
1. Auto-detects the grid (row/column boundaries)
2. Detects player names and substitutions from the left info strip
3. Classifies each PA cell via Gemini 2.5 Flash (cached per cell)
4. Enforces logical constraints (E ≠ out; out → run=False)
5. Applies structural rules (isolation, 3-out, K-PB)
6. Cross-checks against ground-truth totals if present
7. Writes `_cells.json`, `_grid_debug.png`, and `.html` under `games/{stem}/`
8. Imports into `season.db`

### Step 2 — Check the output

Open the generated `.html` widget to visually review the scorecard. Color coding:
- **Green** — hits (1B/2B/3B/HR)
- **Blue** — reached base without a hit (BB/HBP)
- **Yellow** — errors, FC, K-PB
- **Red** — outs

Also read the terminal output for `MISMATCH` lines and constraint violations.

### Step 3 — Edit ground-truth files if needed

**`ground_truth_totals.txt`** — per-inning team totals:
```
# inning  runs  hits  errors  lob
1  3  1  2  0
2  0  2  0  2
```

**`ground_truth_stats.txt`** — per-player H and AB:
```
# slot  H  AB
1  3  4
5  1  4
5  1  1     ← second row for same slot = substitution
```

### Step 4 — Re-run with cache

```powershell
uv run python extract_cells.py "../Quick 2026/scans/2026-06-07 - Almere (Away).jpg" --reuse-cache
```

`--reuse-cache` skips API calls for cells already classified. Structural rules always re-run from scratch. Repeat steps 2–4 until checks pass.

## Correcting a PA after extraction

**Option A — Interactive reviewer** (recommended for low-confidence flags):

```powershell
uv run python review.py --game 2026-06-07          # only low-confidence flags
uv run python review.py --game 2026-06-07 --all    # every PA in the game
```

**Option B — Manual edit:**

1. Edit `Quick 2026/games/{stem}/{stem}_cells.json` — fix `result` / `run_scored`
2. Reimport:

```powershell
uv run python reimport.py "../Quick 2026/games/2026-04-12 - Thamen (Home)/2026-04-12 - Thamen (Home)_cells.json"
```

---

## Reimport all games

After a pipeline fix that affects DB logic (e.g. stat calculation changes), reimport everything:

```powershell
uv run python reimport.py --all "../Quick 2026/games"
```

---

## Export to Excel

```powershell
uv run python export_season.py
```

Output: `Quick 2026/Quick 2026 stats.xlsx`

| Sheet | Contents |
|---|---|
| Season Stats | Cumulative stats for all players, sorted by OPS |
| Game Log | Per-player per-game line |
| {Date} {Opponent} | Box score for each game |
| Low Confidence | PAs flagged for review |

Stats include: AB, H, 2B, 3B, HR, BB, K, R, RBI, AVG, OBP, SLG, OPS, BABIP, ISO, BB%, K%, wOBA, RC, OPS+, AB/HR, BB/K.
Note: BB, HBP, SAC, and SF do not count as an AB.

## Publish outputs

Copy all HTML widgets and the stats xlsx to a shared folder (e.g. Google Drive):

```powershell
uv run python publish.py "../Quick 2026" "G:\My Drive\Quick 2026"
```

## Roster

Player names are detected from the scorecard automatically and fuzzy-matched to the DB. Substitutions share the same batting slot and are detected from the info strip.

```powershell
uv run python manage_players.py list
uv run python manage_players.py aliases    # audit recent fuzzy matches
```

## Notes

- **API key safety**: `.env` is gitignored. Never commit API keys.
- **Re-running a game**: the pipeline replaces any existing DB entry automatically.
- **DB path**: driven by `paths.data_root` in `scorecard/config.yml`.
